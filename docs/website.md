# Website Architecture

## Purpose

The VeliGeldi website is a static marketing and lead-generation site for a preschool student handover product. It is separate from the operational entrance terminal, management application, API, and database.

The website has four primary goals:

1. Explain the product clearly to preschool administrators.
2. Present the available product and pricing information.
3. Provide direct phone, WhatsApp, and contact options.
4. Deliver a fast, accessible experience across mobile and desktop devices.

## Audience and language

The production audience is Turkish-speaking. Customer-facing copy, navigation labels, form messages, and public routes must remain Turkish.

Developer-facing material uses English:

- Source filenames
- JavaScript identifiers
- HTML and CSS comments
- Technical documentation
- Maintenance and deployment scripts

## Client-side behaviour

`website/js/main.js` provides:

- Responsive menu state and ARIA updates
- Modal focus management and focus trapping
- Escape-key and overlay dismissal with trigger-focus restoration
- Reduced-motion-aware reveal animation
- Native form validation
- WhatsApp message construction
- Lazy Google Maps iframe creation
- Unavailable-download feedback

All visible messages generated by JavaScript remain Turkish.

## Shared HTML

Page routes, metadata, and company contact details have one source of truth in
`config/site.mjs`. Shared document heads, headers, contact sections, footers,
floating contact actions, and enquiry dialogs are maintained in
`templates/partials/`. The dependency-free `scripts/sync-shared-html.mjs`
command renders those fragments into the deployable HTML pages. Its `--check`
mode prevents generated pages from drifting in CI.

## Accessibility

- Semantic headings and landmark elements
- Keyboard-operable navigation and modals
- `aria-expanded` updates on the mobile menu
- Accessible labels on icon-only controls
- High-contrast primary actions
- `prefers-reduced-motion` support
- Native form constraints and validation
- Safe POST fallback when JavaScript is unavailable
- Decorative images hidden from assistive technology where appropriate

## Performance

- No framework or runtime dependency
- No production build step
- One shared stylesheet across all pages
- Responsive WebP and JPEG image sources
- Self-hosted fonts and a reusable SVG icon sprite
- Explicit image dimensions to reduce layout shift
- Lazy loading for non-critical media
- Google Maps loaded only after user interaction

## SEO

Each public page contains:

- A unique title and description
- Canonical production URL
- Open Graph and Twitter metadata
- Organization JSON-LD

The website also provides `robots.txt` and `sitemap.xml` using the production domain.

## Automated quality checks

`scripts/validate.mjs` verifies:

- Required metadata and canonical URLs
- Local asset references and SVG symbols
- Unique HTML IDs
- Valid JSON-LD
- Safe contact-form fallbacks
- Absence of inline page styles and duplicated icon sprites
- Guardrails against unsupported product claims

GitHub Actions runs the validator and JavaScript syntax checks for pushes and pull requests.
It also verifies that generated shared HTML blocks match their partials.

## Deployment contract

The production server must:

1. Serve files from the `website/` directory.
2. Map the Turkish public routes to the English HTML source files.
3. Redirect HTTP traffic to HTTPS.
4. Select one canonical hostname and redirect the alternative.
5. Serve static assets with appropriate cache headers.
6. Preserve MIME types for SVG, WebP, WOFF2, JavaScript, and CSS.

The exact Nginx configuration will be created after the Ubuntu VM, network, and DNS configuration have been inspected.

## Change-safety rule

Developer-facing refactors must not change:

- Turkish customer copy
- Public Turkish routes
- Contact details
- WhatsApp message content
- Form behaviour
- Layout or visual styling
